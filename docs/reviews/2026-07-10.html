Zone 1 · Core player pages (5 material)

# File Category Summary + proposed fix
1 TonightPage.tsx:164 Feature gap Last Result card only reads legacy report_text for its blurb. Since we retired that field in favour of structured summary, every new match now hides the blurb behind the generic "Match played — tap to view result" placeholder. Fix: fetch summary too and prefer it over report_text, keeping report_text as legacy fallback.
2 TonightPage.tsx:1021 UI inconsistency <TierLegend /> sits at the very bottom of the page, but its own comment says it exists "so first-time users know what the colours mean without poking at every row" — needs to be visible before the Who's In list. Fix: move it just above the Who's In section header.
3 ProfilePage.tsx:435 UI inconsistency ProfilePage is the only page in the app that skips CeefaxHeader — hand-rolls a back arrow + coloured "My Profile" tagline instead. Breaks the teletext pattern used on 12+ other pages. Fix: replace with <CeefaxHeader pageId="P501 · PROFILE" title="PROFILE" /> and drop the standalone Back button.
4 ProfileCompletionCard.tsx:181 UX friction The "Backup position" (pos2) row mounts the same PositionPicker as "Preferred position" (pos1), with the same onChange — so tapping either row shows a picker for both slots and the user has to figure out which chip controls which. Fix: either (a) collapse to one "Positions" row that marks complete when primary is set, or (b) pass a secondaryOnly prop to the pos2 picker.
5 MotmVotingCard.tsx:324 Accessibility The 🏆 / 🤡 vote pick buttons are 36×36 px — below Apple's HIG 44×44 pt minimum and WCAG 2.5.5's 44×44 CSS-px target. Two sit right next to each other, so on smaller phones mis-votes (DOTD instead of MOTM) are likely. Fix: bump to at least w-11 h-11 and increase gap.

Zone 2 · Content pages (5 material)

# File Category Summary + proposed fix
6 FeedbackPage.tsx:79 UI inconsistency FeedbackPage is the only content page that skips CeefaxHeader — bespoke masthead makes it look like a stranger in the app. Fix: <CeefaxHeader pageId="P810 · FEEDBACK" title="FEEDBACK" /> for both player + admin variants.
7 CupPage.tsx:162 UX friction Sweep tab renders nothing when SweepstakeCard has no entries or is still loading — SweepstakeCard returns null in both cases. Tapping "Sweep" shows a blank page. Fix: either show an "Sweepstake opens when admin seeds the draw" empty state at CupPage level, or have SweepstakeCard render its header + a placeholder body.
8 PodsPage.tsx:15 Feature gap Players without a favourite_club see no Your Club section and no prompt telling them setting one would unlock curated fan pods — the whole section silently vanishes. Fix: when !profile?.favourite_club, render a soft callout above "The Curated List" pointing them to /profile.
9 CardsPage.tsx:170 Accessibility Card-detail modal has no role="dialog", no aria-modal, no aria-labelledby, no ESC-to-close, no focus trap. Screen-reader and keyboard-only users have no way to know it's open or dismiss it. Fix: add ARIA + ESC handler + move initial focus to Close button.
10 CupPage.tsx:913 Accessibility LeaderTable + BestStreakBoard render as nested divs with grid layouts — a proper <table> would give screen-reader users column semantics for RANK / NAME / % / STREAK / PTS. Fix: refactor to semantic table, keep grid CSS on <tr>.

Zone 3 · Admin surfaces (8 material)

# File Category Summary + proposed fix
11 AdminMatchEntry.tsx:200 Content Match Report textarea still writes to legacy report_text — but per CLAUDE.md we now populate structured JSON (summary, predictions, key_highlights) and leave report_text NULL. Filling this field would double-render on the History/Match tabs. Fix: either retire the textarea entirely, or convert to write summary instead.
12 AdminMatchEntry.tsx:923 Feature gap The "Highlights" input writes to a highlights column that no surface renders — orphaned/stalled feature. Fix: either remove the input, or surface highlights on Match/History as a linked video chip.
13 AdminFinancePanel.tsx:257 Data safety markAllPaid clears every unpaid fine + WTP across all months (not just the viewed one) with no confirmation. A misclick wipes months of chase state. Fix: inline confirm banner listing exactly what will be cleared, especially prior-month carryover.
14 AdminFinancePanel.tsx:815 Data safety Fine / WTP / credit deletions fire from 16-18 px ✕ buttons with no confirm, no aria-label, sitting directly next to the Mark Paid toggle. A fat-finger tap destroys the record instead of toggling paid state. Fix: inline confirm-per-row (or long-press pattern), plus aria-label + bigger tap target.
15 AdminFinancePanel.tsx:351 Feature gap No search/filter over the ~60-row finance list — admin scrolls to find the one they want. Sort is by net balance, not by name. Fix: top-of-list name search + quick-filter chips (Owed / In credit / Blocked).
16 AdminPage.tsx:219 Feature gap Same problem in the Players panel: no search over 60 rows. Fix: top-of-list search filtering by name/surname + quick-filter chips (SUB / WTP★ / WTP / missing card_* stats).
17 AdminTeamBuilder.tsx:594 UX friction Success banner "✓ Teams published and visible to players" is gated on draftTeams.length === 0, but publish() never clears draftTeams. So after a successful publish (first-time or re-publish) admin gets no explicit success confirmation — only the button label swap. Fix: clear draftTeams after publish OR drop the length===0 gate; consider a transient toast too.
18 AdminMatchEntry.tsx:197 Code quality Unused nextThursday prop had been quietly disabled with an eslint-suppress. Already fixed inline in the same commit — prop removed from the interface, destructure, and both callsites in MatchPage.
