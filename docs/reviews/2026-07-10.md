# App review · 10 Jul 2026

_Full UX/UI/feature review across 15 pages + key components. Three subagents ran in parallel — one per zone. This doc lists only the **material findings** that need a product decision. The **28 safe inline fixes** have already been applied in the commit below._

Total: **46 findings** — 18 material (below), 28 small (fixed).

## Zone 1 · Core player pages (5 material)

| # | File | Category | Summary |
|---|---|---|---|
| 1 | `src/pages/TonightPage.tsx:164` | feature-gap | Last Result card only reads legacy `report_text` for its blurb. Since we retired that field in favour of structured `summary`, every new match hides the blurb behind the generic "Match played — tap to view result" placeholder. **Proposed**: fetch `summary` too and prefer it over `report_text`, keeping `report_text` as legacy fallback. |
| 2 | `src/pages/TonightPage.tsx:1021` | ui-inconsistency | `<TierLegend />` sits at the very bottom of the page, but its own comment says it exists "so first-time users know what the colours mean without poking at every row" — needs to be visible **before** the Who's In list. **Proposed**: move it just above the Who's In section header. |
| 3 | `src/pages/ProfilePage.tsx:435` | ui-inconsistency | ProfilePage is the only page in the app that skips CeefaxHeader — hand-rolls a back arrow + coloured "My Profile" tagline instead. Breaks the teletext pattern used on 12+ other pages. **Proposed**: replace with `<CeefaxHeader pageId="P501 · PROFILE" title="PROFILE" />` and drop the standalone Back button (bottom nav handles it). |
| 4 | `src/components/ProfileCompletionCard.tsx:181` | ux-friction | The "Backup position" (pos2) row mounts the **same** PositionPicker as "Preferred position" (pos1), with the same onChange — so tapping either row shows a picker for both slots and the user has to figure out which chip controls which. **Proposed**: either (a) collapse to one "Positions" row that marks complete when primary is set, or (b) pass a `secondaryOnly` prop to the pos2 picker. |
| 5 | `src/components/MotmVotingCard.tsx:324` | accessibility | The 🏆 / 🤡 vote pick buttons are 36×36 px — below Apple's HIG 44×44 pt minimum and WCAG 2.5.5's 44×44 CSS-px target. Two sit right next to each other, so on smaller phones mis-votes (DOTD instead of MOTM) are likely. **Proposed**: bump to at least `w-11 h-11` and increase gap. |

## Zone 2 · Content pages (5 material)

| # | File | Category | Summary |
|---|---|---|---|
| 6 | `src/pages/FeedbackPage.tsx:79` | ui-inconsistency | FeedbackPage is the only content page that skips CeefaxHeader — bespoke masthead makes it look like a stranger in the app. **Proposed**: `<CeefaxHeader pageId="P810 · FEEDBACK" title="FEEDBACK" />` for both player + admin variants. |
| 7 | `src/pages/CupPage.tsx:162` | ux-friction | Sweep tab renders **nothing** when SweepstakeCard has no entries or is still loading — SweepstakeCard returns `null` in both cases. Tapping "Sweep" shows a blank page. **Proposed**: either show a "Sweepstake opens when admin seeds the draw" empty state at CupPage level, or have SweepstakeCard render its header + a placeholder body instead of returning null. |
| 8 | `src/pages/PodsPage.tsx:15` | feature-gap | Players without a favourite_club see no Your Club section and no prompt telling them setting one would unlock curated fan pods — the whole section silently vanishes. **Proposed**: when `!profile?.favourite_club`, render a soft callout above "The Curated List" pointing them to `/profile`. |
| 9 | `src/pages/CardsPage.tsx:170` | accessibility | Card-detail modal has no `role="dialog"`, no `aria-modal`, no `aria-labelledby`, no ESC-to-close, no focus trap. Screen-reader and keyboard-only users have no way to know it's open or dismiss it. **Proposed**: add the ARIA + ESC handler + move initial focus to Close button. Moderate size — either roll our own or bring in a headless dialog primitive. |
| 10 | `src/pages/CupPage.tsx:913` | accessibility | LeaderTable + BestStreakBoard render as nested divs with grid layouts — a proper `<table>` would give screen-reader users column semantics for RANK / NAME / % / STREAK / PTS. **Proposed**: refactor to semantic table, keep grid CSS on `<tr>`. |

## Zone 3 · Admin surfaces (8 material)

| # | File | Category | Summary |
|---|---|---|---|
| 11 | `src/components/AdminMatchEntry.tsx:200` | content | Match Report textarea still writes to legacy `report_text` — but per CLAUDE.md we now populate structured JSON (`summary`, `predictions`, `key_highlights` etc) and leave `report_text` NULL. Filling this field would **double-render** on the History/Match tabs. **Proposed**: either retire the textarea entirely (structured JSON is written directly per our convention), or convert to write `summary` instead. |
| 12 | `src/components/AdminMatchEntry.tsx:923` | feature-gap | The "Highlights" input writes to a `highlights` column that no surface renders — orphaned/stalled feature. **Proposed**: either remove the input if abandoned, or surface `highlights` on Match/History (e.g. as a linked video chip). |
| 13 | `src/components/AdminFinancePanel.tsx:257` | data-safety | `markAllPaid` clears **every** unpaid fine + WTP across all months (not just the viewed one) with no confirmation. A misclick wipes months of chase state. **Proposed**: add an inline confirm banner (same pattern as `republishConfirm` in AdminTeamBuilder) that lists exactly what will be cleared, especially prior-month carryover. |
| 14 | `src/components/AdminFinancePanel.tsx:815` | data-safety | Fine / WTP / credit deletions fire from 16-18 px ✕ buttons with no confirm, no aria-label, sitting directly next to the Mark Paid toggle. A fat-finger tap on the row destroys the record instead of toggling paid state. **Proposed**: inline confirm-per-row (or long-press pattern), plus aria-label + bigger tap target. |
| 15 | `src/components/AdminFinancePanel.tsx:351` | feature-gap | No search/filter over the ~60-row finance list — admin scrolls to find the one they want. Sort is by net balance, not by name. **Proposed**: top-of-list name search input + quick-filter chips (Owed / In credit / Blocked). |
| 16 | `src/pages/AdminPage.tsx:219` | feature-gap | Same problem in the Players panel: no search over 60 rows. **Proposed**: top-of-list search filtering by name/surname + quick-filter chips (SUB / WTP★ / WTP / missing card_* stats). |
| 17 | `src/components/AdminTeamBuilder.tsx:594` | ux-friction | Success banner "✓ Teams published and visible to players" is gated on `draftTeams.length === 0`, but `publish()` never clears draftTeams. So after a successful publish (first-time or re-publish) admin gets **no explicit success confirmation** — only the button label swap. **Proposed**: clear draftTeams after publish OR drop the length===0 gate; consider a transient toast too. |
| 18 | `src/components/AdminMatchEntry.tsx:197` | code-quality | (Rolled into #11) — `nextThursday` prop already removed inline. |

## Recurring loop

- `scripts/weekly-review.mjs` + `.github/workflows/weekly-review.yml` land in the same commit as this doc.
- Every **Monday 07:00 BST** a static checklist gets committed to `docs/weekly-reviews/YYYY-Www.md` with churn / TODOs / bundle-size / stale-page metrics.
- The checklist's "Suggested focus areas" section names the top-3 hottest files that week — those are the surfaces most likely to have new copy or new states that need eyes.
- When something on the checklist looks worth a deeper look, invoke a Claude session with the prompt at the bottom of the weekly file — it spins up subagents, produces categorised findings, applies the small ones, and reports the material ones (this doc is the template).
- **No Anthropic API cost** for the recurring loop — deep reviews happen on-demand only.
