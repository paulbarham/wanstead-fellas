Web Push Notifications · Runbook
P517 · RUNBOOK
What this is. One-page reference for the match-night push notification system (shipped 5 Jul 2026). Two flows: admin one-off setup (repeat only if a secret rotates), and player opt-in (each device, once). Bottom: the four errors you're likely to hit while wiring it up, with the fix for each.

How it works. Admin submits a match result → voting_windows row inserts → Postgres trigger calls the edge function → the function fetches rostered players' push subscriptions, signs a VAPID JWT, encrypts the payload and hands it to Apple / FCM / Mozilla → the browser's service worker renders "🏆 Vote for tonight's awards" on the player's device. Same flow when results publish, different payload.

🛠️ Admin — one-off setup

Done once. Only redo if a secret rotates or the function goes missing.
1 Generate a VAPID keypair. Any machine with node: npx web-push generate-vapid-keys --json. Public key = safe to publish. Private key = secret.
2 Hardcode the public key in the client. Lives at src/lib/push.ts as VAPID_PUBLIC_KEY. Browsers use this to sign the subscription request.
3 Set project secrets. Dashboard → Settings → Edge Functions → Secrets. Add VAPID_PRIVATE_KEY and VAPID_SUBJECT = mailto:pabarham@gmail.com.
4 Deploy the edge function. Dashboard → Edge Functions → Deploy → paste supabase/functions/send-vote-notifications/index.ts, name it send-vote-notifications, turn OFF Verify JWT.
5 Store the function URL in Vault. One SQL call: vault.create_secret(<url>, 'vote_notify_url', 'desc'). The trigger reads it — never hardcoded.
6 Wire the triggers. Migration 048 creates voting_windows_notify_open_trg (INSERT) and voting_windows_notify_results_trg (UPDATE OF results_published). Apply and you're done.

📱 Player — per-device opt-in

Each player, each device, once. iOS needs Home Screen install first.
1 Open the app from the Home Screen icon — not from Safari. iOS only allows web push from an installed PWA. If you haven't added it: share sheet → Add to Home Screen.
2 Go to Profile. Tap the avatar in the top-right of any tab.
3 Tap "Enable notifications" on the 🔔 Match-night notifications card. Grant permission when the browser prompts. The card flips green ON.
4 Done. After the next Thursday match, when the admin submits the result, your phone gets pinged. Tap it to jump straight into the ballot.

Change your mind? Same card → "Turn off on this device". Blocked by mistake in Safari? Site Settings → Notifications → Allow, then re-enable in the app.

Troubleshooting — the four errors you'll hit

404 Requested function was not found Fix: the edge function isn't deployed. Redeploy via Dashboard. Confirm the vault URL matches the deployed name exactly (hyphens, not underscores).
401 UNAUTHORIZED_NO_AUTH_HEADER Fix: Verify JWT is still on. Toggle off on the function's Details page. Our pg_net call intentionally sends no auth header.
500 VAPID_PRIVATE_KEY not configured Fix: add the private key as a project secret. Case-sensitive, no trailing whitespace. Redeploy so the env is picked up.
403 BadAuthorizationHeader (Apple) Fix: VAPID public key at send-time doesn't match the one the browser signed the subscription with. Either add VAPID_PUBLIC_KEY as a project secret, or match the hardcoded fallback to src/lib/push.ts.

Diagnostic path

Fire a manual test from SQL — the response includes the exact status code + body for any failure:

SELECT public.call_send_vote_notifications(
  (SELECT id FROM matches WHERE status='completed' ORDER BY match_date DESC LIMIT 1), 'vote_open');
SELECT pg_sleep(4);
SELECT status_code, content FROM net._http_response
WHERE created > NOW() - INTERVAL '30 seconds' ORDER BY id DESC LIMIT 1;

Success: {"sent":1,"total":1,"results":[{"ok":true}]}. Anything else: results[].statusCode + body map to one of the four errors above.
